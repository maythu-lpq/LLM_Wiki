# Project Name: Organic Chemistry Reaction Mechanism LLM Wiki & Learning Hub

## 1. Project Purpose
This project aims to build a personalized **LLM Wiki Knowledge Base** and **Interactive Web Guide** covering the four core Organic Chemistry reaction mechanisms: **SN1, SN2, E1, and E2**. 
The AI agent must extract knowledge from raw textbook PDFs (including both text and visual reaction diagrams), organize it into structured Markdown notes, and generate consistent, well-formatted web pages for studying and Q&A.

## 2. Directory Structure & Naming Rules
The project root directory (`o chem LLM Wiki`) must maintain the following structure:
- `AGENTS.md` / `GEMINI.md`: Project rules and instructions for the AI agent.
- `raw/`: Contains original reference materials (textbook PDF files). **The AI must NEVER modify, rename, or delete files inside `raw/`.**
- `wiki/`: Contains structured Markdown knowledge base files generated by the AI.
  - `wiki/index.md`: Master index and navigation overview of all Wiki entries.
  - `wiki/sn1.md`, `wiki/sn2.md`, `wiki/e1.md`, `wiki/e2.md`: Individual mechanism notes (filenames must be strictly lowercase).
- `index.html`: Main landing page displaying all mechanism cards and a comprehensive comparison table.
- `pages/`: Contains individual HTML learning pages for each mechanism (`pages/sn1.html`, `pages/sn2.html`, `pages/e1.html`, `pages/e2.html`).

## 3. LLM Wiki & Q&A Rules
1. **Multimodal Extraction**: When reading PDFs in `raw/`, analyze both text and visual elements (reaction steps, curved arrow electron flow, stereochemistry wedge/dash configurations, and energy diagrams).
2. **Standard Wiki Note Format**: Every `wiki/*.md` file must include these fixed sections:
   - **Overview**
   - **Kinetics & Rate Law**
   - **Step-by-Step Mechanism**
   - **Stereochemistry**
   - **Controlling Factors** (Substrate, Nucleophile/Base, Leaving Group, Solvent Effects)
   - **Related Mechanisms** (Cross-links using relative paths, e.g., `[SN2 Mechanism](sn2.md)`)
3. **Grounded Q&A Rule**: When answering Organic Chemistry questions, **rely primarily on the knowledge stored in `wiki/`** and cite which `.md` file the answer comes from. If a detail is missing from `wiki/`, clearly inform the user and suggest adding it to the knowledge base.

## 4. Web Design & UI Standards
1. **Visual Style**: Clean, modern academic note style (light background `#F8FAFC`, deep navy accent `#1E3A8A`, structured cards, responsive layout).
2. **Chemical Notation & Diagrams**:
   - Use proper HTML `<sub>` and `<sup>` tags for chemical formulas and charges.
   - Every mechanism page (`pages/*.html`) must include clean **Inline SVG** diagrams illustrating the reaction mechanism (with curved arrows) and a reaction coordinate energy diagram (labeling Transition States and Intermediates).
3. **Consistent Navigation**: Every page in `pages/*.html` must feature a top navigation bar linking back to `../index.html` and switching between all mechanisms.

## 5. Workflow for Adding New Content
Whenever new textbook chapters or reaction mechanisms (e.g., Addition Reactions) are added to `raw/`, the AI must automatically execute:
1. Read the new source file in `raw/` and create a lowercase `.md` note in `wiki/` following Section 3.
2. Update `wiki/index.md` with the new entry link and summary.
3. Generate a matching `.html` page in `pages/` (including SVG diagrams) following Section 4.
4. Update `index.html` at the root directory to add a new navigation card for the added mechanism.

## 6. Shared Assets & Data Rules
- `assets/style.css` and `assets/app.js`: shared styles and scripts. Pages must link to these; do NOT duplicate CSS inside each page.
- `data/questions.json`: quiz questions. Format: {"mechanism": "sn2", "question": "...", "options": [...], "answer": 0, "explanation": "...", "source": "wiki/sn2.md"}
- `data/mechanisms.json`: summary data for each mechanism (used by the search and compare tools).

## 7. Interactive Features (every new mechanism must support these)
- Quiz: add at least 5 questions to `data/questions.json`, each citing its source wiki file.
- Search: new mechanism must appear in `data/mechanisms.json`.
- Predictor: update the decision logic in `assets/app.js` if the new mechanism competes with existing ones.
- Tab titles: plain text only (no HTML tags inside <title>).
- All scripts must be vanilla JavaScript (no build step), so the site works on GitHub Pages.

## 8. Chatbot Rules
- Chatbot page: `pages/chat.html`, using `assets/chat.js`.
- Mode A (default): Load all `wiki/*.md` files via fetch, split by `##` headings into chunks, rank chunks by keyword match with the user's question, and display the best 1-3 chunks as the answer.
- Every answer must cite its source file (e.g. "Source: wiki/sn2.md › Stereochemistry"). Link the citation to the matching `pages/*.html`.
- If no chunk matches, reply: "This is not in the wiki yet. Suggested: add it to wiki/<file>.md."
- NEVER put API keys in any file in this repo. If an LLM backend is added later, call it only through a proxy URL stored in `assets/config.js`.
- Keep the chatbot working when a new mechanism is added: it must auto-read all files listed in `wiki/index.md`.

- Data field names in `data/mechanisms.json` must be lowercase camelCase and identical
  across all mechanisms (name, category, fullName, molecularity, rateLaw, steps,
  intermediate, stereochemistry, regiochemistry, rearrangements, substrate).
  Any JS reading these fields must use exactly these names.
- Never display raw `undefined`: use a fallback ("—") and test every mechanism pair after changes.
